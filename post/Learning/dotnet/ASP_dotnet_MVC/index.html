DotNet学习笔记（一）：ASP.net MVC

1.什么是MVC

  • MVC编程模式 是三种ASP.NET编程模式的一种，使用Model表示应用程序核心，使用View显示数据，Controller处理输入。简单说来就是Model代表数据库，View代表前端，Controller代表后端。
  • 创建应用程序 从Visual Studio创建程序时，选择ASP.NET Web Application，不使用Core。创建后点击MVC即可创建出ASP.net MVC应用程序。

2.应用程序文件夹与文件分析

  • App_Data文件夹 用于存储应用数据程序，类似于SQL数据库等。
  • App_Start文件夹 用于存储应用程序的配置，路由，日志等相关代码。
  • Content文件夹 用于放置静态文件，样式表（CSS文件），图标和图像等。
  • Controllers文件夹 用于放置出力用户输入和响应的控制器类，要求所有的.cs控制器文件以Controller结尾。代表MVC中的C。
  • Models文件夹 用于放置应用程序模型的类。代表MVC中的M。
  • Scripts文件夹 用于放置应用程序的JS文件，默认情况下，在这个文件夹中存放标准的 MVC、Ajax 和 jQuery 文件。
  • Views文件夹 用于放置表示用的HTML文件。文件夹中包含每个Controller对应的文件夹，以及一个共享用的Shared文件夹。
  • favicon.ico文件 用于配置网站的图标。
  • Global.asax 用作应用程序的全局配置，负责初始化应用程序配置以及全局设置。
  • packages.config 记录所有引用的nuget包的信息
  • Web.config 包含网站部署相关的设置与选项，可以定义与应用程序相关的一些配置。

    • 其中配置路由用的MapRoute可以书写多次，其中name参数代表路由规则名，url参数代表路由规则，defaults代表默认匹配。
    • 对于其中{}包裹的内容，代表占位符，即可以变化的内容，假设依据上述的路由规则。访问url为Work/Find/1。则代表向WorkController的FindAction进行请求，请求内容为Id=1。
    • 如果占位符中没有写controller与action，则未书写的部分将使用默认值中的内容。则在defaults内一定要配置未书写的部分。
    • 当有多个路由规则时，则会使用第一个匹配的，不建议多个匹配。
    • 其中的UrlParameter.Optional代表可选参数，即希望即使Id不赋值也可匹配的上。
    • 可以使用RouteDate.Values来获取路由匹配产生的路由数据。
    • 可以使用*来代表匹配URL的剩余部分。如下所示，这时假设使用Work/Find/1/12来访问时，会将1/12作为id传入。
    • 定义默认值时，如果只定义中间占位符的默认值，无效。规则中存在除占位符，/以外的字符时，无效。
    • 如下所示，其中constraints代表路由约束。可以使用正则表达式来约束占位符的书写方式。
    routes.MapRoute(
    name: "Default",
    url: "{controller}/{action}/{*id}",
    defaults: new { controller = "Home", action = "Index", id = UrlParameter.Optional },
    constraints: new {id = @"\d{3}"}
);
